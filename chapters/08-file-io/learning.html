1. The FILE Type and Streams

In C, all input and output operations are performed through streams. A stream is an abstraction that represents a continuous flow of data to or from a device (such as a disk file, terminal, keyboard, network socket, or pipe). This abstraction decouples your C code from the physical storage hardware.

A stream is represented in C programs by a pointer to an opaque structure type named FILE (defined in <stdio.h>). You never inspect or manipulate the internal members of a FILE struct directly; instead, you pass a FILE * handle to the standard library I/O functions.

Standard Streams

When a C program starts execution, the runtime environment automatically opens three standard streams, available as global FILE * constants:

Stream Type Default Device Description
stdin FILE * Keyboard Standard input stream (read by scanf, getchar, fgets)
stdout FILE * Terminal / Display Standard output stream (written by printf, putchar, puts)
stderr FILE * Terminal / Display Standard error stream for diagnostic messages (unbuffered by default)

Stream Buffering Modes

To reduce expensive system calls to the operating system kernel, C streams buffer data in memory before flushing it to the underlying device:

  • Fully buffered (_IOFBF): Characters are accumulated in an internal block buffer and written to disk only when the buffer is full (or flushed explicitly with fflush() or fclose()). Typical for disk files.
  • Line buffered (_IOLBF): Characters are flushed whenever a newline character ('\n') is encountered or the buffer fills up. Typical for interactive output to terminals (stdout).
  • Unbuffered (_IONBF): Characters are written immediately to the destination without any intermediate buffering. Default for stderr so critical error messages appear without delay if a crash occurs.

2. Opening and Closing Files

Files are opened with fopen() and closed with fclose():

file_open_close.c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("data.txt", "r");
    if (fp == NULL) {
        perror("Error opening data.txt");
        return EXIT_FAILURE;
    }

    /* ... perform file operations ... */

    if (fclose(fp) == EOF) {
        perror("Error closing file");
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}

File Access Modes

The second argument to fopen() is a string specifying the file mode:

Mode Meaning If File Exists If File Does Not Exist
"r" Open for reading Reads from start Fails (returns NULL)
"w" Open for writing (truncate/create) Truncates to 0 bytes Creates new file
"a" Open for appending (write at end) Appends to end Creates new file
"r+" Open for reading and writing Positions at start Fails (returns NULL)
"w+" Open for reading and writing (truncate) Truncates to 0 bytes Creates new file
"a+" Open for reading and appending Reads anywhere, writes at end Creates new file
"rb", "wb", "ab" Binary equivalents of the above Same behavior Same behavior
"r+b", "w+b", "a+b" Binary read/update equivalents Same behavior Same behavior
🛑
Always close open files and check return values: Failing to call fclose() causes resource and file descriptor leaks in the operating system. Furthermore, buffered write data is flushed when fclose() runs; if you fail to close a file or if your program crashes, buffered data may never be written to disk.

3. Text Mode I/O

Text mode streams translate line endings transparently. On Windows systems, text mode converts \n in memory to \r\n (CR-LF) on disk upon writing, and converts \r\n back to \n upon reading. On POSIX systems (Linux / macOS), text mode and binary mode are identical.

1. Formatted I/O: fprintf and fscanf

fprintf and fscanf work identically to printf and scanf, but accept a target FILE * stream as their first argument.

formatted_io.c
/* Writing formatted text */
fprintf(fp, "%s %d %.2f\n", "Alice", 20, 3.85);

/* Reading formatted text */
char name[32];
int age;
double gpa;
if (fscanf(fp, "%31s %d %lf", name, &age, &gpa) == 3) {
    printf("Read student: %s, age %d, GPA %.2f\n", name, age, gpa);
}

2. Line-by-Line I/O: fgets and fputs

fgets() is the recommended, buffer-safe function for reading text line-by-line. Unlike the dangerous and removed gets(), fgets() requires specifying the maximum buffer size.

  • char *fgets(char *str, int size, FILE *stream): Reads up to size - 1 characters, stopping after a newline ('\n') or EOF. Stores the newline inside str and appends a null terminator ('\0'). Returns str on success, or NULL on EOF / error.
  • int fputs(const char *str, FILE *stream): Writes null-terminated string str to stream (does NOT automatically append a newline). Returns non-negative integer on success, EOF on error.
fgets_fputs.c
char buffer[256];
while (fgets(buffer, sizeof(buffer), fp) != NULL) {
    fputs(buffer, stdout);
}

3. Character-by-Character I/O: fgetc and fputc

  • int fgetc(FILE *stream): Reads the next character as an unsigned char cast to int, or returns EOF on end-of-file or error.
  • int fputc(int ch, FILE *stream): Writes character ch to stream. Returns the character written, or EOF on error.
💡
Store fgetc() return value in an int, never a char: EOF is a negative integer (typically -1). If you store the return value in a char on platforms where char is unsigned (or if a valid byte matches (char)EOF), the comparison ch != EOF will fail.

4. Binary Mode I/O

Binary streams transfer raw bytes without translating newlines or interpreting null characters. Binary mode is essential for media files, network packets, and structured binary records.

fread and fwrite

  • size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream): Writes nmemb elements of size size bytes each from memory buffer ptr to stream. Returns the number of items successfully written.
  • size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream): Reads up to nmemb elements of size size bytes from stream into buffer ptr. Returns the number of items successfully read.
struct_binary_io.c
#include <stdio.h>

typedef struct {
    int    id;
    char   title[64];
    double price;
} Product;

void save_product(const Product *p, const char *filename) {
    FILE *fp = fopen(filename, "wb");
    if (fp == NULL) return;

    size_t written = fwrite(p, sizeof(Product), 1, fp);
    if (written != 1) {
        perror("Write failed");
    }
    fclose(fp);
}

int load_product(Product *p, const char *filename) {
    FILE *fp = fopen(filename, "rb");
    if (fp == NULL) return 0;

    size_t read_count = fread(p, sizeof(Product), 1, fp);
    fclose(fp);
    return read_count == 1;
}
💡
Portability & Endianness Note: Dumping memory structures directly to disk with fwrite(&struct, sizeof(struct), 1, fp) writes struct padding bytes and architecture-dependent multi-byte integers (Little Endian vs Big Endian). Binary files written this way may not be compatible across different compilers, alignments, or CPU architectures. For robust cross-platform interchange, consider serialisation formats (such as fixed byte layouts, JSON, or protocol buffers).

5. File Positioning (Random Access)

C streams maintain an internal file position indicator that advances as you read or write. You can query or modify this indicator to perform random access I/O.

fseek and ftell

  • int fseek(FILE *stream, long offset, int whence): Repositions the file position indicator. Returns 0 on success, non-zero on error.
  • long ftell(FILE *stream): Returns the current byte offset from the beginning of the file, or -1L on error.
  • void rewind(FILE *stream): Resets the position indicator to the start of the file (equivalent to (void)fseek(stream, 0L, SEEK_SET), plus clearing error flags).

The whence parameter specifies the anchor point for offset:

Constant Anchor Point Example: Seek to 10th byte Example: Seek to end
SEEK_SET Beginning of file fseek(fp, 10L, SEEK_SET) —
SEEK_CUR Current position fseek(fp, 10L, SEEK_CUR) —
SEEK_END End of file — fseek(fp, 0L, SEEK_END)

Measuring File Size with ftell

file_size.c
fseek(fp, 0L, SEEK_END);
long size = ftell(fp);
rewind(fp);
printf("File size: %ld bytes\n", size);

Large Files: fgetpos and fsetpos

Because ftell() and fseek() use long integers, they may overflow on files exceeding 2 GB on 32-bit long systems. C provides fgetpos and fsetpos using the opaque fpos_t type to handle arbitrary file sizes.

fpos_example.c
fpos_t pos;
fgetpos(fp, &pos); /* record current position */
/* ... read or write elsewhere ... */
fsetpos(fp, &pos); /* restore saved position */

6. Error Handling in File I/O

When an I/O operation returns fewer elements than expected or an error indicator, you must determine whether the stream encountered an end-of-file condition or a hardware/OS error.

Inspection Functions

  • int feof(FILE *stream): Returns non-zero if the end-of-file indicator has been set for stream.
  • int ferror(FILE *stream): Returns non-zero if the error indicator has been set for stream.
  • void clearerr(FILE *stream): Clears both the EOF and error indicators for stream.
  • void perror(const char *s): Prints string s, a colon, and the human-readable description corresponding to the current global errno.
  • char *strerror(int errnum) (from <string.h>): Returns a string describing the error code errnum (e.g. errno).
⚠️
Never use while (!feof(fp)) to control read loops: feof() only returns true after a read operation has already attempted to read past the end of the file and failed. If used as the loop condition, your loop body will execute one extra time on garbage/stale data. Always check the return value of your read function (e.g. fgets, fread, fscanf, fgetc) as the loop condition!
correct_eof_handling.c
/* WRONG: Processes last record twice! */
/* while (!feof(fp)) { fscanf(fp, "%d", &val); printf("%d\n", val); } */

/* CORRECT: Check return value directly */
int val;
while (fscanf(fp, "%d", &val) == 1) {
    printf("Read: %d\n", val);
}

/* After loop, check why it terminated */
if (ferror(fp)) {
    perror("I/O error occurred during read");
} else if (feof(fp)) {
    printf("End of file reached successfully.\n");
}

7. Temporary Files

C provides functions in <stdio.h> for creating scratchpad temporary files:

  • FILE *tmpfile(void): Creates and opens a temporary binary file in "wb+" mode. The file is automatically deleted when it is closed or when the program terminates normally.
  • char *tmpnam(char *str): Generates a unique temporary filename.
🛑
Security Caveat with tmpnam: tmpnam() is inherently vulnerable to Time-of-Check to Time-of-Use (TOCTOU) race conditions: between the time tmpnam() generates the name and your program creates the file with fopen(), another process or attacker could create a symlink with that name. Prefer tmpfile() or POSIX mkstemp().
tmpfile_demo.c
#include <stdio.h>

int main(void) {
    FILE *tmp = tmpfile();
    if (tmp == NULL) {
        perror("Failed to create temporary file");
        return 1;
    }

    fputs("Temporary data stored in scratch file\n", tmp);
    rewind(tmp);

    char line[128];
    if (fgets(line, sizeof(line), tmp) != NULL) {
        printf("Read from temp: %s", line);
    }

    fclose(tmp); /* File is automatically deleted from disk */
    return 0;
}

8. Standard Streams Redirection

Standard streams can be redirected programmatically in C or externally through shell operators.

Programmatic Redirection: freopen

FILE *freopen(const char *filename, const char *mode, FILE *stream) closes the existing stream (if open) and reassigns it to open filename. This is commonly used to redirect stdout or stderr to a log file.

freopen_demo.c
#include <stdio.h>

int main(void) {
    printf("This message prints to the console terminal.\n");

    /* Redirect stdout to output.log */
    if (freopen("output.log", "w", stdout) == NULL) {
        perror("freopen failed");
        return 1;
    }

    printf("This message is written to output.log instead!\n");
    return 0;
}

Shell Redirection & Special Devices

In Unix and Windows command lines, you can redirect streams without modifying code:

  • ./prog > out.txt — Redirects stdout to out.txt
  • ./prog < in.txt — Redirects stdin from in.txt
  • ./prog 2> err.log — Redirects stderr to err.log
  • ./prog > /dev/null 2>&1 — Discards both stdout and stderr using the special null sink device (/dev/null on Unix, NUL on Windows).

Summary

  • C abstracts I/O through FILE * streams (stdin, stdout, stderr).
  • Always open files with fopen(), check for NULL, and close with fclose().
  • Use "w" and "w+" with caution: they truncate existing files immediately.
  • For safe text line reading, use fgets() instead of scanf() or gets().
  • For raw binary data and structs, use fread() and fwrite() with "rb"/"wb" modes.
  • Use fseek() (with SEEK_SET, SEEK_CUR, SEEK_END) and ftell() for random access positioning.
  • Never control read loops with feof(); check the read function's return value directly and inspect with ferror() / feof() afterward.
  • Use tmpfile() for auto-deleted temporary files and freopen() to redirect standard streams.
