1. A brief history of C

C was developed between 1969 and 1973 at Bell Labs by Dennis Ritchie, primarily to rewrite the Unix operating system in a portable language. Before C, operating systems were written in assembly language — tightly coupled to a specific processor family.

The language was standardised as ANSI C (C89) in 1989, then as C99, C11, and most recently C17 (ISO/IEC 9899:2018). A new revision, C23, is in the final stages of publication.

"C is a general-purpose programming language which features economy of expression, modern control flow and data structures, and a rich set of operators." — Brian W. Kernighan & Dennis M. Ritchie, The C Programming Language

2. Why learn C in 2024+?

  • Systems programming — operating systems, device drivers, embedded firmware.
  • Performance-critical software — databases, game engines, language runtimes (Python's CPython interpreter is written in C).
  • Understanding the machine — C exposes memory layout, pointers, and hardware in a way no higher-level language does.
  • Foundation for other languages — C++, Objective-C, Go, Rust, and many others are directly inspired by C.
  • TIOBE & industry demand — C consistently ranks in the top 3 most-used languages worldwide.

3. The compilation pipeline

When you run gcc hello.c -o hello, four distinct phases execute in sequence:

#PhaseWhat happensOutput
1Pre-processingHandles #include, #define, macros, conditional compilation.i file
2CompilationTranslates C source to architecture-specific assembly.s file
3AssemblyTranslates assembly mnemonics into binary object code.o file
4LinkingCombines object files + libraries into a single executablea.out / hello.exe
💡
You can inspect intermediate outputs: gcc -E hello.c (preprocessor only), gcc -S hello.c (assembly), gcc -c hello.c (object file only).

4. Anatomy of a C program

Every C program must have exactly one main function — this is the entry point. The runtime calls main when the program starts.

hello.c — annotated
/* 1. Preprocessor directive — tells the compiler to include
      the Standard I/O library header (declares printf, scanf, etc.) */
#include <stdio.h>

/* 2. main() — program entry point.
      int  = return type (exit code returned to the OS)
      void = no command-line arguments accepted (can also be argc/argv) */
int main(void)
{
    /* 3. printf — print formatted text to standard output.
          \n = newline character */
    printf("Hello, World!\n");

    /* 4. return 0 — signals success to the OS (non-zero = error) */
    return 0;
}

5. The printf function

printf (print formatted) is declared in <stdio.h>. It takes a format string followed by optional arguments.

Format specifierTypeExample
%dintprintf("%d", 42); → 42
%ldlong intprintf("%ld", 1000000L);
%fdoubleprintf("%.2f", 3.14159); → 3.14
%ccharprintf("%c", 'A'); → A
%schar * (string)printf("%s", "hello");
%%literal %printf("100%%"); → 100%

6. Return codes and the OS

The value returned by main is the exit status of the program. By convention:

  • return 0; — success
  • return 1; (or any non-zero value) — failure

In a shell you can inspect the last exit code:

bash
./hello
echo $?       # prints 0

This matters in shell scripting and CI pipelines where a non-zero exit terminates the pipeline.

7. Comments in C

C supports two comment styles:

comments.c
/* This is a
   multi-line block comment (C89 style) */

int x = 5;  // This is a single-line comment (C99 and later)
⚠️
Block comments (/* */) do not nest. Writing /* outer /* inner */ */ causes a compile error because the parser treats the first */ as closing the entire comment.

Summary

  • C is a compiled, statically-typed, procedural language created at Bell Labs in the early 1970s.
  • Compilation goes through four stages: pre-processing → compilation → assembly → linking.
  • Every program has a single main function as its entry point.
  • printf is the primary way to produce output; it uses format specifiers and escape sequences.
  • The return value of main becomes the program's exit code.
