Exercise 1 — Type Size Table

Concepts: sizeof is evaluated at compile time and yields a size_t, so it is printed with %zu. The macro uses the stringising operator #T to print the type name without retyping it.

ex1_solution.c
#include <stdio.h>

/*
 * Key concepts: sizeof yields a size_t, so we print it with %zu.
 * A macro keeps the table rows consistent: #T turns the type name into a
 * string literal, and sizeof(T) is evaluated at compile time.
 */
#define ROW(T) printf("%-20s %2zu\n", #T, sizeof(T))

int main(void)
{
    printf("%-20s %s\n", "Type", "Bytes");
    printf("%-20s %s\n", "--------------------", "-----");

    ROW(char);
    ROW(short);
    ROW(int);
    ROW(long);
    ROW(long long);
    ROW(float);
    ROW(double);
    ROW(long double);

    return 0;
}
▶
Output:
Type Bytes
-------------------- -----
char 1
short 2
int 4
long 8
long long 8
float 4
double 8
long double 8
💡
On 64-bit Windows long is 4; on x86-64 Linux long double is 16. Differences from your output are expected and are exactly the point of using sizeof.

Exercise 2 — Temperature Converter

Concepts: floating-point arithmetic. 9.0 / 5.0 forces double division; 9 / 5 would be integer division (= 1) and give the wrong answer. %.2f prints exactly two decimals.

ex2_solution.c
#include <stdio.h>

/*
 * Key concepts: floating-point arithmetic with double, and "9.0 / 5.0".
 * Writing 9 / 5 would be INTEGER division (= 1) and give a wrong answer.
 * Using floating-point literals forces the whole expression into double.
 */
int main(void)
{
    double celsius    = 36.6;
    double fahrenheit = celsius * 9.0 / 5.0 + 32.0;

    printf("Celsius    : %.2f\n", celsius);
    printf("Fahrenheit : %.2f\n", fahrenheit);

    return 0;
}
▶
Output:
Celsius : 36.60
Fahrenheit : 97.88
💡
36.6 × 1.8 + 32 = 97.88.

Exercise 3 — Limits Explorer

Concepts: <limits.h> macros have different types, so each needs a matching specifier (%d for int constants, %u for UINT_MAX). The field width %12d right-aligns numbers.

ex3_solution.c
#include <stdio.h>
#include <limits.h>

/*
 * Key concepts: <limits.h> constants are macros expanding to integer
 * constant expressions. Their types differ, so each needs the matching
 * format specifier: INT_MIN/INT_MAX/CHAR_* are int (%d); UINT_MAX is
 * unsigned int (%u).
 */
int main(void)
{
    printf("%-10s | %12s\n", "Constant", "Value");
    printf("-----------+-------------\n");
    printf("%-10s | %12d\n", "CHAR_BIT", CHAR_BIT);
    printf("%-10s | %12d\n", "CHAR_MIN", CHAR_MIN);
    printf("%-10s | %12d\n", "CHAR_MAX", CHAR_MAX);
    printf("%-10s | %12d\n", "INT_MIN",  INT_MIN);
    printf("%-10s | %12d\n", "INT_MAX",  INT_MAX);
    printf("%-10s | %12u\n", "UINT_MAX", UINT_MAX);

    return 0;
}
▶
Output:
Constant | Value
-----------+-------------
CHAR_BIT | 8
CHAR_MIN | -128
CHAR_MAX | 127
INT_MIN | -2147483648
INT_MAX | 2147483647
UINT_MAX | 4294967295
💡
If CHAR_MIN is 0 and CHAR_MAX is 255 on your machine, plain char is unsigned there (common on ARM Linux).

Exercise 4 — Overflow Detector

Concepts: signed overflow is undefined behaviour, unsigned overflow is well defined. The safe pattern tests the operands before the operation: a > INT_MAX - 1 can never itself overflow.

ex4_solution.c
#include <stdio.h>
#include <limits.h>

/*
 * Key concepts: signed integer overflow is UNDEFINED BEHAVIOUR.
 * The C standard places no requirements on the result: the program might
 * print INT_MIN (typical two's-complement wrap-around), might crash, or the
 * optimiser might delete code on the assumption that overflow never happens.
 *
 * 'volatile' prevents the compiler from folding the addition at compile
 * time, so you see what the hardware does. The "safe" version checks BEFORE
 * adding, which is the only portable way to avoid signed overflow.
 */
int main(void)
{
    volatile int x = INT_MAX;
    int y = x + 1;                       /* undefined behaviour */

    printf("x     = %d\n", x);
    printf("x + 1 = %d\n", y);

    /* Safe version: test first, then add. */
    int a = INT_MAX;
    if (a > INT_MAX - 1) {
        printf("Adding 1 to %d would overflow - skipped.\n", a);
    } else {
        a = a + 1;
    }

    return 0;
}
▶
Output:
x = 2147483647
x + 1 = -2147483648
Adding 1 to 2147483647 would overflow - skipped.
💡
The second line is the typical result at -O0 on two's-complement hardware, but it is not guaranteed. Compiled with optimisation, or by a different compiler, the output may differ or the code may be transformed unpredictably. Compile with -fsanitize=undefined to have the overflow reported at run time.

Exercise 5 — Type Promotion Puzzle

Concepts: integer promotion (char/short → int), usual arithmetic conversions (int → double, signed → unsigned), and the fact that int / int is integer division even when the result is stored in a double.

ex5_solution.c
#include <stdio.h>

/*
 * Key concepts: integer promotion and the usual arithmetic conversions.
 *  - Operands narrower than int are promoted to int first.
 *  - If one operand is floating-point, the other is converted to it.
 *  - If an unsigned operand has the same rank as a signed one, the signed
 *    operand is converted to unsigned (so negative values wrap modulo 2^N).
 */
int main(void)
{
    int          i = 5;
    double       d = 2.5;
    char         c = 'A';
    unsigned int u = 5;
    short        s1 = 200, s2 = 300;
    float        f = 1.5f;

    /* 1. int + double -> double */
    printf("1. 5 + 2.5          = %.1f\n", i + d);

    /* 2. char + int -> int ('A' is 65) */
    printf("2. 'A' + 1          = %d\n", c + 1);

    /* 3. unsigned int - int -> unsigned int; 5 - 10 wraps around */
    printf("3. 5u - 10          = %u\n", u - 10);

    /* 4. int / int is integer division; the result is then widened */
    double q = 7 / 2;
    printf("4. double q = 7 / 2 = %.1f\n", q);

    /* 5. short * short -> int, so 60000 does NOT overflow a short */
    printf("5. 200 * 300        = %d (type size %zu)\n", s1 * s2, sizeof(s1 * s2));

    /* 6. float + double -> double */
    printf("6. sizeof(f + d)    = %zu\n", sizeof(f + d));

    /* 7. Evaluation order matters: left-to-right with conversions */
    printf("7. 1 / 2 * 3.0      = %.1f\n", 1 / 2 * 3.0);
    printf("   3.0 * 1 / 2      = %.1f\n", 3.0 * 1 / 2);

    return 0;
}
▶
Output:
1. 5 + 2.5 = 7.5
2. 'A' + 1 = 66
3. 5u - 10 = 4294967291
4. double q = 7 / 2 = 3.0
5. 200 * 300 = 60000 (type size 4)
6. sizeof(f + d) = 8
7. 1 / 2 * 3.0 = 0.0
3.0 * 1 / 2 = 1.5
💡
Why #3 is 4294967291: 10 is converted to unsigned int, so the result is 5 − 10 = −5 modulo 232 = 4,294,967,291. Why #7 differs: 1 / 2 is evaluated first (integer division → 0) and only then multiplied by 3.0, while 3.0 * 1 is already a double.
