1. Stack vs Heap

Every C process uses two main memory regions for object storage: the stack and the heap.

The Stack (automatic storage)

Local variables and function parameters live on the stack. Memory is allocated automatically when a block is entered and freed automatically when the block exits — you never call any allocation function. This is why local variables are sometimes called automatic variables.

  • Very fast allocation (single register decrement).
  • Size must be known at compile time (or at function-call time for VLAs).
  • Lifetime is tied to the enclosing scope.
  • Typically limited (often 1–8 MB) — large objects or deep recursion trigger a stack overflow.

The Heap (dynamic storage)

The heap is a large pool of memory managed explicitly by the programmer through the standard library allocation functions. You request memory at runtime, use it, and must release it when done.

  • Size can be determined at runtime.
  • Lifetime is controlled entirely by the programmer (from malloc to free).
  • Much larger than the stack — limited mainly by virtual address space and physical RAM.
  • Slower allocation (involves OS and allocator bookkeeping).

2. malloc — Allocate Uninitialised Memory

malloc (memory allocate) requests a contiguous block of at least size bytes from the heap and returns a pointer to the first byte.

malloc_signature.c
#include <stdlib.h>

void *malloc(size_t size);  /* returns void *, or NULL on failure */
  • Returns a void *, which implicitly converts to any pointer type in C.
  • The allocated bytes are uninitialised — their contents are indeterminate garbage.
  • Returns NULL if the allocation fails (out of memory).
  • Always check the return value for NULL before using the pointer.
malloc_example.c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;
    int *arr = malloc(n * sizeof(int));  /* allocate 5 ints */

    if (arr == NULL) {
        fprintf(stderr, "malloc failed\n");
        return 1;
    }

    for (int i = 0; i < n; ++i)
        arr[i] = i * 10;

    free(arr);   /* always free when done */
    arr = NULL;  /* prevent dangling pointer */
    return 0;
}
💡
Always write sizeof(Type) or sizeof *ptr in the malloc call — never hardcode byte sizes like malloc(20). This keeps the code portable across platforms with different type sizes.

3. calloc — Allocate Zero-Initialised Memory

calloc (counted allocate) allocates memory for n objects of size bytes each and zero-initialises every byte.

calloc_signature.c
void *calloc(size_t nmemb, size_t size);

Compared with malloc(n * size):

  • Zero-initialisation: All allocated bytes are set to 0.
  • Overflow-safe counting: The library checks internally that nmemb * size does not overflow size_t; malloc(n * size) can silently overflow, allocating far too little memory.
calloc_example.c
#include <stdio.h>
#include <stdlib.h>

typedef struct { int x; int y; } Point;

int main(void) {
    int n = 3;
    Point *pts = calloc(n, sizeof(Point));  /* all fields are 0 */
    if (!pts) { perror("calloc"); return 1; }

    printf("pts[0].x = %d (should be 0)\n", pts[0].x);

    free(pts);
    pts = NULL;
    return 0;
}

4. realloc — Resize an Allocation

realloc changes the size of a previously allocated block. It may move the block to a new location if the original location cannot be extended.

realloc_signature.c
void *realloc(void *ptr, size_t new_size);

Key rules:

  • Returns a pointer to the (possibly relocated) block, or NULL on failure.
  • If realloc fails, the original block is untouched — it is not freed.
  • realloc(NULL, size) behaves exactly like malloc(size).
  • realloc(ptr, 0) behaviour is implementation-defined; treat it as equivalent to free(ptr).
🛑
Never realloc into the same pointer: ptr = realloc(ptr, n) leaks the original block if realloc returns NULL. Always use a temporary: void *tmp = realloc(ptr, n); if (tmp) ptr = tmp;
realloc_safe.c
#include <stdlib.h>
#include <stdio.h>

int main(void) {
    int *arr = malloc(4 * sizeof(int));
    if (!arr) return 1;

    /* Safe realloc pattern — NEVER write arr = realloc(arr, ...) */
    int *tmp = realloc(arr, 8 * sizeof(int));
    if (tmp == NULL) {
        fprintf(stderr, "realloc failed\n");
        free(arr);   /* original block still valid — free it */
        return 1;
    }
    arr = tmp;  /* now safe to update arr */

    free(arr);
    arr = NULL;
    return 0;
}

5. free — Release Heap Memory

free(ptr) returns the block pointed to by ptr to the heap allocator. ptr must have been returned by a prior malloc, calloc, or realloc call.

  • free(NULL) is explicitly defined to be a safe no-op.
  • After freeing, set the pointer to NULL to prevent accidental use.
🛑
Double-free is Undefined Behaviour. Calling free(p) twice on the same pointer corrupts the allocator's internal data structures and is a common source of security vulnerabilities (heap corruption, arbitrary code execution).
🛑
Use-after-free is Undefined Behaviour. Reading or writing through a pointer after free has been called on it can silently corrupt data or crash the program with unpredictable timing. Always set freed pointers to NULL.

6. Memory Layout of a C Process

A typical 64-bit Linux process virtual address space is divided into named segments:

process_memory_layout.txt
High addresses (e.g. 0xFFFF...)
┌────────────────────────────┐
│  Stack  (grows ↓ downward)  │  ← local variables, return addresses
├────────────────────────────┤
│          (gap)             │
├────────────────────────────┤
│  Heap   (grows ↑ upward)   │  ← malloc / calloc / realloc
├────────────────────────────┤
│  BSS  (uninitialised data)  │  ← global/static vars = 0
├────────────────────────────┤
│  Data (initialised data)   │  ← global/static vars with values
├────────────────────────────┤
│  Text (code / read-only)   │  ← compiled machine instructions
└────────────────────────────┘
Low addresses  (e.g. 0x0000...)

The heap and stack grow toward each other. Modern OSes map memory on demand using virtual memory, so neither region actually occupies physical RAM until it is touched.

8. Detecting Memory Errors

Valgrind

Valgrind is the gold-standard Linux tool for runtime memory analysis. It instruments your binary to track every allocation and every memory access.

valgrind_usage.sh
# Compile with debug symbols
gcc -std=c17 -Wall -g -o myprog myprog.c

# Run under Valgrind with full leak checking
valgrind --leak-check=full --track-origins=yes --error-exitcode=1 ./myprog

Valgrind reports: definite leaks, indirect leaks, uninitialised reads, invalid reads/writes, and double-frees.

AddressSanitizer (ASan)

AddressSanitizer is a compiler-instrumented sanitiser built into GCC and Clang. It detects heap and stack buffer overflows, use-after-free, and use-after-return at near-native speed.

asan_usage.sh
# Enable AddressSanitizer and optional leak check
gcc -std=c17 -Wall -g -fsanitize=address -fno-omit-frame-pointer -o myprog myprog.c
./myprog

GCC Stack Protector

The -fstack-protector-strong flag inserts canary values below return addresses to detect stack-based buffer overflows at runtime:

stack_protector.sh
gcc -std=c17 -Wall -fstack-protector-strong -o myprog myprog.c

9. Best Practices

RAII-style wrappers

In C, there is no automatic destructor, but you can adopt the discipline of writing small allocation and cleanup functions that always come in pairs:

raii_style.c
/* Always pair: alloc → use → free before every return path */
int *arr = malloc(n * sizeof(int));
if (!arr) goto cleanup;
/* ... use arr ... */
cleanup:
    free(arr);
    arr = NULL;

Always-free pattern

Use a single exit path (via goto cleanup or a single return at the end) to ensure free is always called, even on error paths.

Ownership semantics

Document clearly which function owns (is responsible for freeing) each allocated block. In large codebases, pass ownership through naming conventions and comments:

ownership.c
/*
 * Returns a heap-allocated string — CALLER MUST FREE.
 */
char *build_greeting(const char *name);

Summary

  • Stack memory is automatic and fast; heap memory is manual and flexible.
  • malloc(n) allocates n uninitialised bytes; always check for NULL.
  • calloc(count, size) allocates zero-filled memory and is overflow-safe.
  • realloc(ptr, new_size) resizes a block; always use a temporary pointer to detect failure.
  • free(ptr) releases heap memory; free(NULL) is safe; set pointer to NULL after freeing.
  • Double-free and use-after-free are undefined behaviour and serious security bugs.
  • Use Valgrind (--leak-check=full) or AddressSanitizer (-fsanitize=address) to catch memory errors.
  • Document ownership clearly; always ensure every allocation has a matching free on every code path.
