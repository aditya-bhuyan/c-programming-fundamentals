1. Defining a struct

Arrays group values of the same type. A structure (struct) groups values of different types under one name, so related data travels together. Each value inside a struct is called a member (or field).

Declare the struct type once, then create variables of that type. Access a member with the dot operator (.):

struct_syntax.c
struct Tag {
    type1 member1;
    type2 member2;
    /* ... */
};                          /* the trailing semicolon is required */
define_struct.c
#include <stdio.h>
#include <stddef.h>

struct Student {
    char   name[20];
    int    age;
    double gpa;
};

int main(void) {
    struct Student s;                 /* declare a variable of the struct type */
    s.age = 20;                       /* member access with the dot operator   */
    s.gpa = 3.7;
    snprintf(s.name, sizeof s.name, "Alice");

    printf("%s, age %d, GPA %.1f\n", s.name, s.age, s.gpa);

    printf("offsetof name = %zu\n", offsetof(struct Student, name));
    printf("offsetof age  = %zu\n", offsetof(struct Student, age));
    printf("offsetof gpa  = %zu\n", offsetof(struct Student, gpa));
    printf("sizeof        = %zu\n", sizeof(struct Student));

    return 0;
}

Output (the offsets assume a typical 64-bit platform):

Output
Alice, age 20, GPA 3.7
offsetof name = 0
offsetof age  = 20
offsetof gpa  = 24
sizeof        = 32

Memory layout, size and padding

The members of a struct are stored in memory in declaration order, at increasing addresses. The first member always starts at offset 0. However, CPUs read most efficiently when a value sits at an address that is a multiple of its size (its alignment), so the compiler inserts unused padding bytes between members, and sometimes after the last one.

MemberTypeOffsetBytes
namechar[20]020
ageint204
gpadouble248

Here name (20 bytes) ends exactly at offset 20, which is already 4-byte aligned for int, so no padding is needed before age. age ends at offset 24, which is 8-byte aligned for double, so again no padding. This layout happens to be padding-free, and the total of 32 bytes is a multiple of 8, the strictest member alignment. The next example shows padding actually appearing.

padding_demo.c
#include <stdio.h>

struct Padded {
    char a;     /* 1 byte  + 3 bytes padding */
    int  b;     /* 4 bytes                   */
    char c;     /* 1 byte  + 3 bytes padding */
};

struct Reordered {
    int  b;     /* 4 bytes                   */
    char a;     /* 1 byte                    */
    char c;     /* 1 byte  + 2 bytes padding */
};

int main(void) {
    printf("sizeof(struct Padded)    = %zu\n", sizeof(struct Padded));
    printf("sizeof(struct Reordered) = %zu\n", sizeof(struct Reordered));
    return 0;
}
Output
sizeof(struct Padded)    = 12
sizeof(struct Reordered) = 8
ℹ️
Padding is real, but it is not portable. sizeof(struct S) can be larger than the sum of its members, and the exact value depends on the compiler and platform. Always use sizeof and offsetof (from <stddef.h>) instead of hard-coding sizes. Ordering members from largest to smallest alignment usually minimises padding.

Never compare two structs with == (it does not compile) and never compare them with memcmp unless you have zeroed the padding bytes, because padding contents are unspecified.

2. Struct initialisation

A struct can be initialised with a brace-enclosed list. There are three styles you should know:

  • Positional: values are matched to members in declaration order. Fragile if the struct definition changes.
  • Designated initialisers (C99): .member = value, in any order. Self-documenting and robust.
  • Partial initialisation: any member you leave out is set to zero (0, 0.0, or NULL).

The idiom = {0} zero-initialises every member and is the standard way to start from a clean slate. (The standard guarantees the members are zeroed; it does not promise anything about padding bytes.)

init_styles.c
#include <stdio.h>

struct Config {
    int         width;
    int         height;
    const char *title;
    double      scale;
};

int main(void) {
    /* Positional: members are filled in declaration order */
    struct Config a = { 640, 480, "Positional", 1.0 };

    /* Designated initialisers (C99): any order, name the members */
    struct Config b = { .title = "Designated", .width = 800, .height = 600, .scale = 2.0 };

    /* Partial: unnamed members are zero-initialised */
    struct Config c = { .width = 1024 };

    /* Zero-init everything */
    struct Config d = {0};

    /* Arrays of structs can use designated indices too */
    struct Config list[3] = { [1] = { .width = 320, .height = 200 } };

    printf("a: %d x %d \"%s\" %.1f\n", a.width, a.height, a.title, a.scale);
    printf("b: %d x %d \"%s\" %.1f\n", b.width, b.height, b.title, b.scale);
    printf("c: %d x %d title=%s scale=%.1f\n", c.width, c.height, c.title ? c.title : "(null)", c.scale);
    printf("d: %d x %d title=%s scale=%.1f\n", d.width, d.height, d.title ? d.title : "(null)", d.scale);
    printf("list[0].width=%d list[1].width=%d list[2].width=%d\n",
           list[0].width, list[1].width, list[2].width);

    return 0;
}
Output
a: 640 x 480 "Positional" 1.0
b: 800 x 600 "Designated" 2.0
c: 1024 x 0 title=(null) scale=0.0
d: 0 x 0 title=(null) scale=0.0
list[0].width=0 list[1].width=320 list[2].width=0
💡
A local struct variable declared without an initialiser holds indeterminate garbage, exactly like a local int. Get into the habit of writing struct S s = {0};. Variables with static storage duration (globals and static locals) are zero-initialised automatically.

3. Structs and functions

Structs are first-class values in C: you can assign one to another, pass one to a function, and return one from a function.

  • Pass by value: the whole struct is copied into the parameter. The function cannot change the caller's struct. Fine for small structs; wasteful for large ones.
  • Pass by pointer: only an address is copied (typically 8 bytes). The function reads and writes the original through ->. Add const when the function must not modify it.
  • Return by value: the function builds a struct and returns a copy. Convenient for small structs such as points and vectors.

For a pointer p to a struct, p->member is shorthand for (*p).member. The parentheses are needed because . binds tighter than unary *.

struct_functions.c
#include <stdio.h>

struct Counter {
    int hits;
    int misses;
};

/* By value: receives a COPY, caller's struct is untouched */
void record_hit_copy(struct Counter c) {
    c.hits++;
}

/* By pointer: modifies the caller's struct */
void record_hit(struct Counter *c) {
    c->hits++;
}

/* const pointer: read-only access without copying */
void print_counter(const struct Counter *c) {
    printf("hits=%d misses=%d\n", c->hits, c->misses);
}

/* Return a struct by value */
struct Counter make_counter(int hits, int misses) {
    struct Counter c = { hits, misses };
    return c;
}

int main(void) {
    struct Counter c = make_counter(0, 0);

    record_hit_copy(c);
    print_counter(&c);      /* hits=0 : the copy was modified */

    record_hit(&c);
    print_counter(&c);      /* hits=1 : the original was modified */

    return 0;
}
Output
hits=0 misses=0
hits=1 misses=0
💡
Rule of thumb: pass small, read-only structs by value; pass anything large, or anything the function must modify, by pointer (const if read-only). Never return a pointer to a local struct, because the local is destroyed when the function returns (see Chapter 6).

4. typedef

typedef creates a new name for an existing type. It does not create a new type. Common uses:

  • Struct typedef: lets you write Point instead of struct Point.
  • Primitive alias: gives a meaningful name to a basic type and lets you change it in one place.
  • Function pointer typedef: turns the awkward declarator syntax into a readable name.
typedef_demo.c
#include <stdio.h>

/* Struct typedef: no need to write "struct" every time */
typedef struct {
    int x;
    int y;
} Point;

/* Primitive alias: documents intent and eases porting */
typedef unsigned int uint;
typedef double       Celsius;

/* Function pointer typedef: much easier to read */
typedef int (*Comparator)(int, int);

static int ascending(int a, int b)  { return a - b; }
static int descending(int a, int b) { return b - a; }

static int compare_with(Comparator cmp, int a, int b) {
    return cmp(a, b);
}

int main(void) {
    Point p = {2, 5};
    uint count = 3;
    Celsius temp = 21.5;

    printf("p = (%d, %d), count = %u, temp = %.1f\n", p.x, p.y, count, temp);
    printf("ascending(3, 8)  = %d\n", compare_with(ascending, 3, 8));
    printf("descending(3, 8) = %d\n", compare_with(descending, 3, 8));

    return 0;
}
Output
p = (2, 5), count = 3, temp = 21.5
ascending(3, 8)  = -5
descending(3, 8) = 5

Without the typedef, a function taking a comparator would be declared as int compare_with(int (*cmp)(int, int), int a, int b). With Comparator it reads naturally.

You can also combine a tag with a typedef: typedef struct Node { ... } Node;. The tag is required if the struct refers to itself (next section). A typedef of an anonymous struct, typedef struct { ... } Point;, has no tag and cannot be forward-declared.

5. Nested and self-referential structs

A struct member can itself be a struct. Chain the dot operator to reach inner members: p.position.x. The inner struct is stored inside the outer one, so the outer struct's size includes it.

A struct cannot contain a member of its own type, because its size would be infinite. It can contain a pointer to its own type, since a pointer has a fixed size. This self-referential pattern is the foundation of linked lists, trees and graphs.

nested_and_node.c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    double x;
    double y;
} Vec2;

typedef struct {
    Vec2 position;      /* a struct member that is itself a struct */
    Vec2 velocity;
    int  id;
} Particle;

/* Self-referential: a struct may hold a POINTER to its own type */
typedef struct Node {
    int          value;
    struct Node *next;      /* "Node" is not yet a typedef name here */
} Node;

int main(void) {
    Particle p = { .position = {1.0, 2.0}, .velocity = {0.5, -0.5}, .id = 7 };
    printf("particle %d at (%.1f, %.1f)\n", p.id, p.position.x, p.position.y);

    p.position.x += p.velocity.x;      /* chain the dot operator */
    printf("after move: (%.1f, %.1f)\n", p.position.x, p.position.y);

    /* Build 1 -> 2 -> NULL by hand (full coverage in Chapter 9) */
    Node *second = malloc(sizeof *second);
    Node *first  = malloc(sizeof *first);
    if (first == NULL || second == NULL) {
        free(first);
        free(second);
        return 1;
    }
    second->value = 2;  second->next = NULL;
    first->value  = 1;  first->next  = second;

    for (const Node *cur = first; cur != NULL; cur = cur->next) {
        printf("%d -> ", cur->value);
    }
    printf("NULL\n");

    free(second);
    free(first);
    return 0;
}
Output
particle 7 at (1.0, 2.0)
after move: (1.5, 2.0)
1 -> 2 -> NULL
ℹ️
This is only a preview of linked lists. Allocating nodes with malloc and freeing them is covered in depth in Chapter 9 (Dynamic Memory), and you will build one in Exercise 3.

6. Unions

A union is declared like a struct, but all of its members share the same memory. Only one member is active at a time: writing one member overwrites the others. The size of a union is the size of its largest member (rounded up to satisfy alignment).

union_demo.c
#include <stdio.h>

union Value {
    int    i;
    float  f;
    char   bytes[8];
};

int main(void) {
    union Value v;

    printf("sizeof(union Value) = %zu\n", sizeof(union Value));

    v.i = 65;
    printf("v.i = %d\n", v.i);

    v.f = 1.0f;                           /* overwrites the same bytes */
    printf("v.f = %.1f\n", v.f);
    printf("v.i = 0x%08X  (bit pattern of 1.0f reinterpreted as int)\n", (unsigned)v.i);

    return 0;
}
Output
sizeof(union Value) = 8
v.i = 65
v.f = 1.0
v.i = 0x3F800000  (bit pattern of 1.0f reinterpreted as int)
⚠️
Union aliasing. Reading a union member other than the one last written reinterprets the stored bytes. In C99 and later this "type punning" through a union is permitted, but the resulting value depends on endianness, representation and padding, and the value can be a trap representation. Reading the wrong member is a classic source of bugs. Use a tag to remember which member is valid.

Tagged unions

The safe way to use a union is to pair it with a tag, usually an enum, stored next to it in a struct. Code checks the tag before touching the payload. This pattern, a tagged union (or variant), is how C programs model "this value is either an int or a float or ...".

tagged_union.c
#include <stdio.h>

typedef enum { NUM_INT, NUM_FLOAT } NumKind;

typedef struct {
    NumKind kind;               /* the tag */
    union {
        int   i;
        float f;
    } as;                       /* the payload */
} Number;

static void print_number(const Number *n) {
    switch (n->kind) {
        case NUM_INT:   printf("int %d\n",     n->as.i); break;
        case NUM_FLOAT: printf("float %.2f\n", n->as.f); break;
    }
}

int main(void) {
    Number a = { .kind = NUM_INT,   .as.i = 7 };
    Number b = { .kind = NUM_FLOAT, .as.f = 2.5f };

    print_number(&a);
    print_number(&b);
    return 0;
}
Output
int 7
float 2.50

The nested union { ... } as; is an anonymous-type member named as, so you write n->as.i. Always switch on the tag, and handle every enumerator.

7. Enumerations (enum)

An enumeration defines a set of named integer constants. By default the first enumerator is 0 and each following one is the previous plus one. You can assign explicit values, and numbering continues from the last explicit value.

enum_demo.c
#include <stdio.h>

enum Weekday { MON, TUE, WED, THU, FRI, SAT, SUN };      /* 0, 1, 2, ... 6 */

enum Level { LOW = 10, MEDIUM = 20, HIGH = 30 };         /* explicit values */

enum Mixed { A, B, C = 10, D, E };                       /* 0, 1, 10, 11, 12 */

#define OLD_RED   0                                       /* macro: no type, no scope */
#define OLD_GREEN 1

int main(void) {
    enum Weekday today = WED;
    enum Level   lvl   = HIGH;

    printf("today = %d, lvl = %d\n", today, lvl);
    printf("A=%d B=%d C=%d D=%d E=%d\n", A, B, C, D, E);
    printf("sizeof(enum Weekday) = %zu\n", sizeof(enum Weekday));

    int n = today + 1;                  /* enums are integers: arithmetic compiles */
    printf("today + 1 = %d\n", n);
    printf("OLD_GREEN = %d\n", OLD_GREEN);
    (void)OLD_RED;

    return 0;
}
Output
today = 2, lvl = 30
A=0 B=1 C=10 D=11 E=12
sizeof(enum Weekday) = 4
today + 1 = 3
OLD_GREEN = 1

Underlying type

In C, the enumeration constants (MON, HIGH, ...) always have type int. The enumerated type itself (enum Weekday) is compatible with an implementation-defined integer type that can represent all its values. In practice that is unsigned int or int, hence sizeof(enum Weekday) is typically 4. C does not stop you assigning any integer to an enum variable, so range-checking is your job.

enum versus #define

enum#define
Handled byCompilerPreprocessor (text substitution)
ScopeNormal block / file scopeNone; global from the point of definition
Auto-numberingYesNo, each value written by hand
Debugger visibilityName is visibleUsually just the number
Non-integer valuesNo (integers only)Yes (floats, strings, expressions)

Prefer enum for related integer constants and #define (or const) for everything else. Because enumerators share the surrounding scope, prefix them (NUM_INT, NUM_FLOAT) to avoid name clashes.

8. Bit-fields

A bit-field is a struct member with an explicit width in bits, written type name : width;. Bit-fields pack several small values into one storage unit, which is useful for hardware registers, protocol headers and flag sets.

bitfield_demo.c
#include <stdio.h>

struct Flags {
    unsigned int ready : 1;     /* 1 bit : 0..1  */
    unsigned int error : 1;     /* 1 bit : 0..1  */
    unsigned int mode  : 3;     /* 3 bits: 0..7  */
    unsigned int count : 4;     /* 4 bits: 0..15 */
};

int main(void) {
    struct Flags f = {0};

    f.ready = 1;
    f.mode  = 5;
    f.count = 9;

    printf("ready=%u error=%u mode=%u count=%u\n", f.ready, f.error, f.mode, f.count);
    printf("sizeof(struct Flags) = %zu\n", sizeof(struct Flags));

    /* &f.ready would be a compile error: bit-fields have no address */
    return 0;
}
Output
ready=1 error=0 mode=5 count=9
sizeof(struct Flags) = 4

The four fields use 1 + 1 + 3 + 4 = 9 bits, but they live inside one 4-byte unsigned int storage unit, so the struct is 4 bytes.

⚠️
Portability caveats. The C standard leaves much about bit-fields implementation-defined: the order of bits within a storage unit (low-to-high or high-to-low), whether a field may straddle a storage-unit boundary, and whether a plain int bit-field is signed. You cannot take the address of a bit-field (&f.ready is an error), and sizeof and layout vary between compilers. Use unsigned int explicitly, and never rely on bit-fields to match an on-disk or on-wire format. For that, use explicit shifts and masks.

Summary

  • A struct groups members of different types; access them with ., or with -> through a pointer (p->m is (*p).m).
  • Members are stored in declaration order; the compiler adds padding for alignment, so sizeof can exceed the sum of the members.
  • Prefer designated initialisers; = {0} zero-initialises everything.
  • Structs are copied on assignment, on pass-by-value and on return. Pass by (const) pointer to avoid copies or to modify the original.
  • typedef creates aliases for structs, primitives and function pointers; it does not create a new type.
  • A struct may contain other structs, and pointers to its own type (the basis of linked lists), but not itself.
  • A union shares one block of memory among its members, sized for the largest. Pair it with an enum tag to make a safe tagged union.
  • An enum defines named integer constants; they are scoped and auto-numbered, unlike #define.
  • Bit-fields pack small values into bits, but their layout is implementation-defined, so avoid them for external data formats.
