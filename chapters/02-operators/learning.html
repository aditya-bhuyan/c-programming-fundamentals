1. Arithmetic operators

C provides five binary arithmetic operators. They work on integer and floating-point types (except %, which requires integers).

OperatorMeaningExampleResult
+Addition7 + 29
-Subtraction7 - 25
*Multiplication7 * 214
/Division7 / 23 (both operands int)
%Remainder (modulo)7 % 21

Integer division truncates

When both operands are integers, / performs integer division and discards the fractional part (it truncates toward zero). Make at least one operand floating-point to get a real result.

arith.c
int    a = 7 / 2;          /* 3    : int / int -> int, fraction discarded  */
double b = 7 / 2;          /* 3.0  : division happens first, THEN converts */
double c = 7.0 / 2;        /* 3.5  : one operand is double                 */
double d = (double)7 / 2;  /* 3.5  : cast one operand before dividing      */
int    r = 7 % 2;          /* 1    : remainder                             */

Modulo with negative numbers

In C89, if either operand of / is negative, whether the quotient rounds toward or away from zero was implementation-defined, so the sign of % was too. Since C99, division always truncates toward zero and the result of % takes the sign of the left operand (the dividend). The identity (a / b) * b + a % b == a always holds.

Expression/ result% result (C99+)
7 / 2, 7 % 231
-7 / 2, -7 % 2-3-1
7 / -2, 7 % -2-31
-7 / -2, -7 % -23-1
⚠️
Division or modulo by zero is undefined behaviour for integers. Always check the divisor first. Also note that % is a compile-time error with float/double; use fmod() from <math.h> instead.

2. Relational operators

Relational (comparison) operators compare two values.

OperatorMeaningExampleResult
==Equal to5 == 51
!=Not equal to5 != 50
<Less than3 < 51
>Greater than3 > 50
<=Less than or equal5 <= 51
>=Greater than or equal3 >= 50

The result of a relational expression has type int and is always exactly 0 (false) or 1 (true). Classic C has no built-in bool type (C99 adds _Bool / <stdbool.h>, but comparisons still yield int). In a condition, any non-zero value counts as true.

relational.c
int a = (3 < 5);          /* a == 1 */
int b = (3 > 5);          /* b == 0 */
int c = (3 < 5) + (4 < 9); /* c == 2 : results are ordinary ints */
if (42) { /* true: any non-zero value */ }
🛑
Common mistake: = vs ==. = assigns; == compares. Writing if (x = 5) assigns 5 to x and the condition is always true. Compile with -Wall to get a warning, and consider the "Yoda" style if (5 == x), which fails to compile if you drop an =.
eq_bug.c
int x = 0;
if (x = 5) {          /* BUG: assigns 5 to x; condition is 5 -> true */
    printf("always runs, x is now %d\n", x);
}
if (x == 5) {         /* correct comparison */
    printf("x equals 5\n");
}

3. Logical operators

Short-circuit evaluation

&& and || evaluate left to right and stop as soon as the result is known:

  • A && B — if A is false, B is never evaluated.
  • A || B — if A is true, B is never evaluated.

This is both an optimisation and a safety idiom: the left operand can guard the right one.

short_circuit.c
int *p = NULL;
if (p != NULL && *p > 0) { /* *p is only read when p is not NULL */ }

int d = 0;
if (d != 0 && 10 / d > 1) { /* division by zero is never attempted */ }

int i = 0;
int r = (i != 0) && (++i > 0);   /* left is false -> ++i NOT executed; i stays 0 */
int s = (i == 0) || (++i > 0);   /* left is true  -> ++i NOT executed; i stays 0 */
💡
Don't put essential side effects (function calls, ++) on the right-hand side of && or || unless you intend them to be conditional.

4. Bitwise operators

Bitwise operators work on the individual bits of integer operands. Don't confuse them with the logical operators: & is bitwise AND, && is logical AND.

OperatorNameRule
&AND1 only if both bits are 1
|OR1 if either bit is 1
^XOR1 if the bits differ
~NOT (complement)flips every bit
<<Left shiftshifts bits left, filling with 0
>>Right shiftshifts bits right (sign bit behaviour of negative values is implementation-defined)
bitwise.c
unsigned char a = 0x0C;     /* 0000 1100 = 12 */
unsigned char b = 0x0A;     /* 0000 1010 = 10 */

a & b;                      /* 0000 1000 =  8  both bits set        */
a | b;                      /* 0000 1110 = 14  either bit set       */
a ^ b;                      /* 0000 0110 =  6  bits differ          */
(unsigned char)~a;          /* 1111 0011 = 243 every bit flipped    */
a << 2;                     /* 0011 0000 = 48  (12 * 4)             */
a >> 2;                     /* 0000 0011 =  3  (12 / 4)             */

Use cases

  • Flags — pack several on/off options into one integer.
  • Masking — extract a group of bits with &.
  • Fast multiply/divide by powers of 2 — x << n is x * 2n; x >> n is x / 2n for non-negative values. Modern compilers do this for you, so prefer readable * and / unless you are really manipulating bits.
flags.c
#define FLAG_A (1u << 0)            /* 0000 0001 */
#define FLAG_B (1u << 1)            /* 0000 0010 */
#define FLAG_C (1u << 2)            /* 0000 0100 */

unsigned flags = 0;                 /* 0000 0000 */
flags |=  FLAG_A;                   /* set    : 0000 0001 */
flags |=  FLAG_C;                   /* set    : 0000 0101 */
flags ^=  FLAG_B;                   /* toggle : 0000 0111 */
flags &= ~FLAG_C;                   /* clear  : 0000 0011 */
if (flags & FLAG_A) { /* test: bit 0 is on */ }

unsigned value = 0xABCD;
unsigned low_byte = value & 0xFFu;  /* mask: 0xCD */
unsigned high_byte = (value >> 8) & 0xFFu; /* 0xAB */
⚠️
Shifting by a negative amount, or by an amount greater than or equal to the width of the (promoted) type, is undefined behaviour. Left-shifting a signed value into the sign bit is also problematic. Prefer unsigned types for bit manipulation.

5. Assignment operators

= stores the value of its right operand in its left operand. Each compound assignment operator x op= y is shorthand for x = x op y (with x evaluated only once).

assign.c
int x = 10;
x += 5;     /* 15 */
x -= 3;     /* 12 */
x *= 2;     /* 24 */
x /= 5;     /* 4  (integer division) */
x %= 3;     /* 1  */

int a, b, c;
a = b = c = 0;   /* assignment is right-associative: a = (b = (c = 0)) */

6. Increment and decrement

++ adds 1 and -- subtracts 1. Each comes in two forms that differ in the value of the expression, not in the final value of the variable.

FormNameExpression valueSide effect on x
++xPre-incrementthe new valuex is incremented first
x++Post-incrementthe old valuex is incremented after the value is taken
--xPre-decrementthe new valuex is decremented first
x--Post-decrementthe old valuex is decremented after the value is taken
incdec.c
int x = 5;
int a = x++;    /* a = 5, x = 6 : old value used, then increment */
int b = ++x;    /* x = 7, b = 7 : increment, then new value used */
int c = x--;    /* c = 7, x = 6 */
int d = --x;    /* x = 5, d = 5 */

Side effects in expressions: the undefined-behaviour trap

Modifying the same variable more than once between two sequence points (or modifying it and also reading it for another purpose) is undefined behaviour. The compiler may produce any result.

ub_trap.c
int i = 1;
int a = i++ + i++;       /* UNDEFINED: i modified twice, unsequenced     */
int b = i + i++;         /* UNDEFINED: i read and modified, unsequenced  */
i = i++;                 /* UNDEFINED in C99/C11 (unsequenced)           */
int arr[3] = {0};
arr[i] = i++;            /* UNDEFINED: which i is used for the index?    */

/* Fix: one side effect per statement */
int j = 1;
int c = j + j;
j++;
🛑
The rule of thumb: never use a variable twice in the same expression if one of the uses modifies it (++, --, or an assignment). Split the expression across statements. Note that &&, ||, ?: and the comma operator do introduce a sequence point after evaluating their first operand, so i++ && i++ is well-defined; function-call arguments, however, are not sequenced relative to each other.

7. Operator precedence and associativity

Precedence decides which operator binds tighter (* before +). Associativity decides the grouping of operators of the same precedence (a - b - c is (a - b) - c). The table lists all C operators from highest to lowest precedence.

Two historical quirks cause many bugs: the bitwise operators &, ^, | bind looser than ==, and +/- bind tighter than <</>>.

precedence.c
int a = 2 + 3 * 4;          /* 14 : * first                                  */
int b = 10 - 4 - 3;         /* 3  : left-assoc -> (10 - 4) - 3               */
int c = 6 & 2 == 2;         /* 0  : parsed as 6 & (2 == 2) -> 6 & 1          */
int d = (6 & 2) == 2;       /* 1  : parentheses express the intent           */
int e = 1 + 2 << 3;         /* 24 : (1 + 2) << 3                             */
💡
Use parentheses to make intent explicit. Nobody should need to memorise 15 levels to read your code. Parenthesise anything that mixes bitwise, shift, logical or comparison operators, even where the precedence would already be correct.

8. The ternary and comma operators

Conditional (ternary) operator

condition ? expr_if_true : expr_if_false is C's only three-operand operator. It evaluates condition; if non-zero it evaluates and yields the second operand, otherwise the third. Only the chosen branch is evaluated.

ternary.c
int a = 12, b = 7;
int max = (a > b) ? a : b;               /* 12 */
int abs_v = (b < 0) ? -b : b;            /* 7  */
printf("%s\n", (a % 2 == 0) ? "even" : "odd");

/* Nested -- legal, but hurts readability: */
const char *s = a < 0 ? "negative" : a == 0 ? "zero" : "positive";

Comma operator

The comma operator evaluates its left operand, discards the result, then evaluates the right operand and yields its value. There is a sequence point between the two. It has the lowest precedence of any operator. It is rarely needed outside for loop headers.

comma.c
int x = (1, 2, 3);                     /* x == 3 : last value wins           */

int i, j;
for (i = 0, j = 10; i < j; i++, j--) { /* two variables stepped together     */
    /* ... */
}

int a = 1, b = 2;     /* NOT the comma operator: this is a declaration list   */
int c = (a++, b++);   /* comma operator: a becomes 2, b becomes 3, c == 2     */
💡
The commas separating function arguments (f(a, b)) and declarators (int a, b;) are not comma operators. To pass a comma expression as one argument, wrap it in parentheses: f((a, b)).

Summary

  • Integer / truncates toward zero; % takes the sign of the dividend (C99+). Never divide by zero.
  • Relational and logical operators yield an int that is exactly 0 or 1; confusing = with == is a classic bug.
  • && and || short-circuit: the right operand may never be evaluated.
  • Bitwise operators (& | ^ ~ << >>) act on individual bits — use them for flags, masks and shifts, preferably on unsigned types.
  • Compound assignment (+=, <<=, …) is shorthand for x = x op y.
  • x++ yields the old value, ++x the new one; modifying a variable twice in one expression is undefined behaviour.
  • Precedence and associativity decide grouping; use parentheses to make intent explicit.
  • ?: selects between two expressions; the comma operator sequences them. Use both sparingly.
