1. The if / else if / else Statement

In C, programs execute sequentially line-by-line unless directed otherwise. Conditional statements allow code paths to branch based on Boolean conditions. In C, 0 evaluates to false and any non-zero value evaluates to true.

The basic syntax forms are:

if_syntax.c
/* Simple if */
if (condition) {
    /* executes if condition is non-zero (true) */
}

/* if - else */
if (condition) {
    /* executes when true */
} else {
    /* executes when false */
}

/* Multi-way branch: if - else if - else */
if (score >= 90) {
    printf("Grade A\n");
} else if (score >= 80) {
    printf("Grade B\n");
} else if (score >= 70) {
    printf("Grade C\n");
} else {
    printf("Grade F\n");
}

The Dangling Else Problem

When nested if statements are written without curly braces, an ambiguity arises over which if an else belongs to. In C, the rule is strict:

C Rule: An else clause always associates with the closest preceding unmatched if at the same nesting level.

Consider this misleadingly indented code:

dangling_else.c — dangerous omission of braces
/* WARNING: Indentation does NOT dictate binding in C! */
if (x > 0)
    if (y > 0)
        printf("Both are positive\n");
else
    printf("x is not positive (BUG: this executes when x > 0 and y <= 0!)\n");

Even though the else aligns visually with the outer if (x > 0), the C compiler attaches it to the inner if (y > 0). If x = 5 and y = -1, the program prints "x is not positive"!

💡
Best Practice: Always use braces {} — even for single-statement bodies. Omitting braces is a frequent source of severe security and logic bugs (such as Apple's infamous goto fail bug). Explicit braces make intent clear and future code additions safe.

2. The switch / case Statement

When you need to test a single integer expression against multiple discrete constant values, a switch statement is often cleaner and faster than a long chain of if ... else if statements.

switch_syntax.c
switch (expression) {
    case constant1:
        /* statements */
        break;
    case constant2:
        /* statements */
        break;
    default:
        /* executes if no case matches */
        break;
}

Fall-Through Behaviour and break

Unlike some modern languages, C switch cases fall through by default. When a matching case is found, execution begins there and continues straight through all subsequent cases until a break statement or the end of the switch block is encountered.

This allows deliberate grouping of multiple cases sharing identical behavior:

grouping_cases.c
char ch = 'e';

switch (ch) {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        printf("'%c' is a vowel\n", ch);
        break;
    default:
        printf("'%c' is not a lowercase vowel\n", ch);
        break;
}
⚠️
Accidental Fall-Through: Forgetting a break statement causes execution to run into the next case silently. Always comment intentional fall-through with /* FALLTHROUGH */ to signal intent to compilers and reviewers.
❌
Integer Types Only: In C, switch expressions and case labels must evaluate to integer types (such as int, char, short, long, or enum). You cannot switch on floating-point numbers (float, double), strings, or structs.

When to Use switch vs if-else

ScenarioRecommended ConstructReason
Discrete integer/enum/character choicesswitchClean syntax, compiler can generate fast jump tables (O(1))
Range checks (e.g. x >= 10 && x <= 20)if / else ifcase labels must be compile-time constants
Floating-point comparisons (float, double)if / else ifswitch does not support float types
Compound conditions (x > 0 && y == 2)if / else ifswitch tests only a single expression value

3. The while Loop

The while loop is a pre-condition loop: the condition expression is evaluated before each iteration. If the condition is false initially, the loop body does not execute at all (0 iterations).

while_loop.c
int count = 1;

while (count <= 5) {
    printf("Count: %d\n", count);
    count++;  /* Update step: essential to avoid infinite loop */
}

/* Infinite loop pattern */
while (1) {
    /* runs indefinitely until break is called */
    if (some_event) {
        break;
    }
}

4. The do-while Loop

The do-while loop is a post-condition loop: the condition is checked after the loop body executes. Therefore, the body is guaranteed to run at least once.

dowhile_loop.c
int choice;

do {
    printf("1. Start Game\n");
    printf("2. High Scores\n");
    printf("3. Exit\n");
    printf("Enter choice: ");
    /* Process input... */
} while (choice < 1 || choice > 3);  /* NOTE: semicolon required here */
💡
Primary Use Case: Input validation and menu display. You must prompt the user at least once before you can inspect whether their input was valid or not.

5. The for Loop

The for loop consolidates loop initialization, condition testing, and iteration updates into a single compact header line:

for_syntax.c
for (initialization; condition; update) {
    /* loop body */
}

Execution Order

  1. Initialization: Evaluated exactly once when entering the loop (e.g. int i = 0 in C99+).
  2. Condition: Evaluated before every iteration. If non-zero (true), body runs; if 0 (false), loop terminates.
  3. Body: The block of code inside the loop executes.
  4. Update: Evaluated after the body finishes (e.g. i++). Control then loops back to Step 2.

Optional Clauses and Multiple Expressions

All three parts of a for loop are optional:

  • for (;;) — An infinite loop (equivalent to while (1)). In C, an omitted condition defaults to true.
  • Using the comma operator ,, you can initialize and update multiple variables simultaneously:
multi_var_for.c
/* Iterate with two indices moving in opposite directions */
for (int i = 0, j = 10; i < j; i++, j--) {
    printf("i = %d, j = %d\n", i, j);
}

Nested Loops

Loops can be nested inside other loops. For each single iteration of the outer loop, the inner loop completes its full set of iterations:

nested_grid.c
for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 4; col++) {
        printf("(%d,%d) ", row, col);
    }
    printf("\n");
}

6. Jump Statements: break and continue

  • break — Immediately terminates the innermost enclosing for, while, do-while, or switch statement. Control transfers to the statement following the block.
  • continue — Skips the rest of the current iteration. In while and do-while, control jumps straight to the condition evaluation. In a for loop, control jumps straight to the update expression (e.g. i++) before evaluating the condition.
⚠️
No Labeled Breaks in C: Unlike languages like Java or JavaScript (break outerLoop;), C does not support labeled break statements. A break in C only ever exits the single innermost loop or switch.

7. The goto Statement

C provides the unconditional jump operator goto, which transfers execution to a named label within the same function:

goto_cleanup.c — Linux kernel style error handling
int process_file(const char *filename) {
    int status = 0;
    FILE *f = fopen(filename, "r");
    if (!f) return -1;

    char *buffer = malloc(1024);
    if (!buffer) {
        status = -2;
        goto cleanup_file;  /* Jump to clean up previously acquired file */
    }

    /* ... do work ... */

cleanup_buffer:
    free(buffer);
cleanup_file:
    fclose(f);
    return status;
}

Valid vs Invalid Use Cases for goto

  • Valid (Standard C idiom): Centralized cleanup and resource deallocation on error (as shown above in systems and kernel code), or breaking out of deeply nested loops.
  • Avoid: Jumping backwards, jumping into the middle of loops or blocks, or replacing standard loop constructs. Overuse creates unstructured "spaghetti code" that is difficult to trace and maintain.

8. Loop Performance and Optimization Tips

1. Hoist Invariants Out of Loops

Expressions whose values do not change across iterations should be computed once before the loop begins rather than re-evaluated every cycle:

hoisting.c
/* BAD: strlen() runs on EVERY iteration -> O(N^2) complexity */
for (int i = 0; i < strlen(str); i++) {
    /* ... */
}

/* GOOD: Hoist invariant outside loop -> O(N) complexity */
size_t len = strlen(str);
for (size_t i = 0; i < len; i++) {
    /* ... */
}

2. Prefer Counting Down to Zero When Order Does Not Matter

CPUs often set zero and sign flags automatically when decrementing a register (e.g. subs / test). Comparing against 0 (e.g. while (--n >= 0) or for (int i = N; i-- > 0;)) can save an explicit comparison instruction on low-level architectures.

Summary

  • Conditionals: if/else branches on non-zero (true) vs 0 (false). Always use curly braces to avoid dangling-else ambiguities.
  • Switch: switch operates on integer types only. Remember break to prevent unintended fall-through.
  • Loops: while tests at the top (0+ iterations); do-while tests at the bottom (1+ iterations); for integrates initialization, condition, and update.
  • Loop Control: break exits the innermost loop/switch; continue jumps to the next iteration (to update clause in for).
  • goto: Limit goto to centralized error/resource cleanup and breaking nested loops.
